- 审查结论：代码和隔离网络测试通过，真实 DeepSeek 联调待验收。

## 第四步 多轮修改

- 两轮修改始终携带原文、当前脚本、最近对话和本次要求。
- 节目设置按实际传入字段合并，不因只传音色或时长而重置其他字段。
- 脚本失败不创建新版本，成功后保存独立快照和 UTF-8 脚本。
- 阶段测试：48 项通过，ruff、mypy 通过。
- 综合自查补充：首次生成失败后允许原会话通过 revise 重试；实际音色发布时写回会话，后续修改保留音色。两项均先以回归测试复现，再修复。
- 审查结论：业务流程已实现，真实多轮内容质量待验收。

## 第五步 TTS 与音频

- Qwen-TTS 注册到工具体系，子类仅覆盖请求构造与响应解析，统一模板处理网络错误。
- 下载只接受阿里云域名并升级为 HTTPS，不跟随重定向，不向音频地址转发 Authorization。
- 同时检查 Content-Length 和实际流式字节数；检查 WAV 是否完整可读，拒绝截断文件。
- 使用项目随包 FFmpeg 实际规范化 WAV；参数数组调用、隐藏 Windows 进程窗口，不拼接 shell。
- 测试解码样本值验证拼接顺序；缓存键包含文本、角色、音色、模型、语言、地址与格式。
- 缺段不生成完整节目；成功缓存可保留供重试，不能把缓存片段当成完整成品。
- 阶段测试：54 项通过，ruff、mypy 通过；综合检查补充重定向和截断文件测试。
- 审查结论：本地音频处理通过；真实千问音色和协议权限待验收。

## 第六步 API 与任务

- 202 提交、轮询进度、恢复会话、结构化产物、Range 播放和下载均有测试。
- 后台失败释放会话互斥并保留脚本／旧成品；终态不可回退；重启恢复仅标记中断。
- 返回固定错误信息，422 不回显原材料，502 不泄露路径或上游正文。
- 文件访问验证索引、文件存在性与 output/ 边界，不把内部路径模型发给客户端。
- 健康检查只返回配置状态，不返回密钥。无静态页面、无 CORS、无浏览器操作。
- 综合测试实际执行 API → 后台服务 → LangGraph → SQLite → TTS 协议 → FFmpeg，供应商 HTTP 为测试隔离；检查单一 trace_id 串联全部事件。
- 补充并修复历史任务产物混入后续音色制作结果的问题：产物同时关联 job_id 与 revision_id，旧任务结果保持稳定，避免产物与 trace_id 对不上。
