# C 文稿编辑室前端设计

用户于 2026-10-24 明确选择 C。配色、字体和布局以 .cc-design/design-system.json 为准。当前只确定设计，不连接后端、不修改 API、不请求模型或语音服务。

## 页面组织

- 顶部为产品名称、制作节目入口、使用说明和新建节目，不增加账号或历史节目库。
- 居中标题和简短说明引导用户开始制作，不设置与操作无关的宣传区。
- 桌面左侧：文本材料、字符计数、听众、风格、目标时长、两个角色音色、先预览开关和主按钮。
- 桌面右侧：节目标题、真实音频播放器、实际时长、下载入口、脚本／提纲／审校页签，以及持续修改输入框。
- 会话及请求标识置于可展开区域；验收和录屏时可以展开显示。
- 窄屏改为上下排列：先材料与设置，后进度与成品；字号与按钮保持可操作，不沿用风格比较稿的 800px 最小宽度。

## 必须覆盖的状态

| 状态 | 应呈现的内容与动作 |
| --- | --- |
| 首次进入 | 空材料引导、可选示例输入；不出现虚构成品或可播放的假音频 |
| 材料不合法 | 清楚提示空输入或字符超限，不静默截断 |
| 正在制作 | 按实际阶段显示整理、编写、审校、配音、合成；不伪造百分比或剩余时间 |
| 脚本已就绪 | 展示实际脚本与审校结果，允许修改或单独生成音频 |
| 音频已就绪 | 展示对应版本的音频、实际时长、播放与下载 |
| 脚本已有新版 | 旧音频继续可用，明确提示“此音频对应上一版脚本”，提供生成新版音频入口 |
| 制作失败 | 保留已有结果，显示可读原因，允许用户重试；不自动反复请求供应商 |
| 页面刷新 | 对接阶段通过保存的 session_id 恢复现有会话，不建立不存在的历史列表功能 |

制作中禁用重复提交，原文与设置仍可查看。后端没有取消接口，因此不设计取消任务按钮。音色没有独立试听接口，因此第一版不提供虚构试听。

## 交互约定

“先预览脚本”开启时主按钮为“生成双人脚本”，关闭时为“生成双人播客”。目标时长是参考值，成品只展示返回的实际时长。

脚本按主持人／嘉宾分段展示；听众与风格使用中文标签，对接时映射后端枚举。快捷操作为缩短节目、讲得更通俗、调整音色，不引入新的业务模块。

下载只使用后端返回的产物 URL，不从正文解析路径。错误状态需同时覆盖 HTTP 错误和 HTTP 200 下的 failed 任务。后续轮询在终态停止，旧任务产物不能混入新任务的结果。

键盘操作、清晰焦点、字段标签、错误提示、颜色对比和 375／768／1024／1440px 布局须在正式静态页面自查。浏览器不保存 API Key。

## 当前边界

现有 previews/editorial.html 是展示成品布局的设计稿，内容和波形均为显式标注的示意。后续正式页面必须实现真实空状态，再在设计完成后连接 API；不以当前示意代替端到端验收。

当前已补充 editorial/index.html 完整静态交互稿：默认空白引导，六种状态手动切换，桌面双栏、手机上下排列；主按钮根据输入、音色和预览开关更新；支持键盘切换页签及打开／关闭帮助。音频没有 src，下载入口不提供假成品。静态自查结果见 editorial/review.json，仍未调用 API。
